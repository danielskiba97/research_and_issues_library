# A-003 — D-003 duplicate label names allowed

Addresses: D-003. States: S14. Tests: TC-018.
Root cause: `lib/column-configuration.ts` enforced name uniqueness across each column's labels (message "Labels must be unique and nonempty."), and `lib/model.ts` enforced the same rule for every column type; Monday treats label names as non-unique display strings.
Files: lib/column-configuration.ts, lib/model.ts.
Approach: change uniqueness enforcement to label-ID uniqueness ("Label IDs must be unique.") for Status columns; remove the duplicate-color save block; keep dropdown-value uniqueness in `lib/model.ts` limited to dropdown-type columns (parity with Monday's independent chips).
Expected result: renaming any label to an existing name is accepted; both labels coexist with separate IDs and their own colors; cells bound by label ID keep their values.
Shared-component impact: none outside Status label editing (dropdown columns unchanged).
Verification required: TC-018 replay on both products.
