# D-004 — Used-label delete affordance differs (disabled control vs post-click error)

**Category:** Interaction / Error handling
**Related states:** S16 (deactivated/used label menu)
**Related test cases:** TC-021

## Summary
Monday keeps "Delete label" enabled for a used label and shows an inline error after clicking. Pipeline disables the "Delete label" control for a used label and explains via a tooltip.

## Monday behaviour
The used label's "..." menu still lists "Delete label" (enabled). Clicking it yields the inline error "You can't delete a label while in use". The label is retained.

## Pipeline behaviour
The used label's options menu shows "Delete label" greyed out (disabled) with the help tooltip "This label is in use. Make it inactive instead." For an unused label (Done) the Delete control is enabled. Deactivate remains available for used labels.

## Reproduction steps
1. Apply a label to an item so it is in use.
2. Open Edit Labels and open that label's options menu.
3. Inspect the Delete label control.

## Expected result (Monday reference)
Delete is clickable and returns the error "You can't delete a label while in use" after clicking.

## Actual Pipeline result
Delete is disabled up-front with the tooltip "This label is in use. Make it inactive instead."

Both products block the deletion; the affordance model differs (preventive vs reactive). Also note the related wording diff in the deactivate menu ("Reactivate label" on Monday vs "Activate label" on Pipeline) observed during the deactivate round-trip.
