# D-001 — Label capacity limit not enforced before creation on Pipeline

**Category:** Functional / Validation (boundary)
**Related states:** S11 (at max), S12 (beyond max)
**Related test cases:** TC-013, TC-014, TC-015

## Summary
Monday removes the "+ New label" affordance at exactly 40 labels, so a 41st label cannot be attempted. Pipeline still shows the button at 40 labels and creates a 41st label that persists to the data store; only after creation does the button become disabled with a tooltip.

## Monday behaviour
At 40 saved labels the "+ New label" button is removed entirely from the Edit Labels editor. No error message and no disabled state appear; the 41st label cannot be attempted through the UI.

## Pipeline behaviour
At 40 labels the "+ New label" button remains present and enabled. Clicking it creates a 41st label row, which is persisted to SQLite (data/pipeline.sqlite, table workspace). The button then becomes disabled with the help tooltip "Status columns support up to 40 labels."

## Reproduction steps
1. Open a Status column with 39 labels in Edit Labels.
2. Click "+ New label" once to reach 40 (Monday: button disappears; Pipeline: still present).
3. Click "+ New label" again (Pipeline only) — a 41st label is created and saved.

## Expected result (Monday reference)
Label count is capped at 40 by removing the affordance; no 41st label can be created via the UI.

## Actual Pipeline result
41 labels persist in the data store; the cap is enforced only by disabling the button after over-creation.
